# 最適化後の再プロファイルと実装パターンの比較

すべて `--release`、opt-level=3、ThinLTO、codegen-units=1で比較した。
今回はビルド設定を変えず、前回採用した版を基準に実装だけを変えた。
第0版と前回版のアーカイブ・実行ファイルは保持している。

## 計測対象を固定

以前の固定小数点マンデルブロー（76×25、48反復）を使用する。
画像のBASIC09を移植した現在の `examples/mandel.c`（79×25、実数・16反復）とは別の負荷。
元のソースは `benchmarks/mandel_fixed.c`、元のROM・SDイメージ・入力スクリプトは
`artifacts/benchmark/fixed-inputs/` に凍結し、`benchmarks/fixed-inputs.json` にSHA-256を記録した。
比較ツールは使用前にこれらのハッシュを検査する。

全候補で元の出力SHA-256、描画490,703,662サイクル、総563,528,763サイクルが一致した。
デモのCプログラムやSDドライバの修正が、エミュレータの速度比較に混ざらない構成にした。

## 再プロファイル

前回のインライン展開により、CPU命令処理やメモリ処理が `run` などの呼び出し元へ取り込まれている。
関数シンボルの自己時間だけで `run` をCLIの負荷とみなすことはできない。

ソース行情報付きreleaseビルドを作り、perfを無効状態で開始し、描画バナーを受信した時点で有効化した。
起動・コンパイルのサンプルは除外。制御コマンド反映までの小さな遅延はある。
997Hzの `cpu-clock:u`、変更前970サンプル、採用後905サンプル。
集計は同じ命令位置のインライン情報を辿り、最も内側のプロジェクト関数へ1回だけ帰属させる。
最適化で行情報が欠ける部分など、約7〜9%は未解決として残した。割合は概数。

| ソース上の処理 | 前回版 | 採用後 |
|---|---:|---:|
| メモリアドレス変換 `physical` | 18.9% | 10.6% |
| 命令実行 `execute` | 11.6% | 15.4% |
| indexed計算 `index` | 10.5% | 9.6% |
| indexed等のレジスタ選択 `reg` | 4.8% | 4.4% |
| I/Oアドレス判定 `is_io` | 8.4% | 7.9% |
| CCフラグ更新 `flag` | 5.1% | 5.7% |

同じサンプルを親関数と子関数の両方へ加算していない。
割合の増加は処理そのものの遅化とは限らない。他が速くなれば相対比率は上がる。
採用後は、命令処理・indexedアドレス計算・残ったアドレス変換とI/O判定が次の候補になる。

## 個別に比較したパターン

ウォームアップ後3回ずつの一次比較。以下は固定小数点マンデルブローの中央値。
各行は個別の試作であり、効果を足し算できるわけではない。

| パターン | 秒 | 判断 |
|---|---:|---|
| IRQなしなら割り込み関数を呼ばない分岐 | 0.984 | 明確な改善なし |
| `read16/write16` の `#[inline]` | 0.958 | 小さな改善。他変更後の寄与は小さく、採用見送り |
| 同じ箇所の `#[inline(always)]` | 0.966 | 強い指定の利点なし |
| indexedレジスタを4択の専用matchにする | 0.975 | 明確な改善なし |
| MMU変換を事前計算する | 0.849 | MMU使用時に改善、通常RAMでは低下 |
| CC更新をビットマスク式にする | 0.929 | この負荷では改善。他負荷での低下があり見送り |
| MMUなしの直接RAM経路を残す | 0.876 | 通常RAMの低下を縮小 |
| 上記の表を `Box<Mapping>` へ分離 | 0.862 | 複数負荷のバランスが良く採用 |

キャッシュ・フラグ式・word inlineの組み合わせでは約0.804〜0.838秒まで短縮したが、
通常RAMのループが約8%遅くなったため採用しなかった。
最速のマンデルブローだけを選ぶことは避け、通常RAMとI/Oの負荷も確認した。

## 採用した構成

1. MMUレジスタが変わったときに、8ページ分のRAM先頭位置と書き込み可否を計算する。
2. MMU無効時は従来の直接RAMアクセスを使い、変換表を読まない。
3. 変換表は `Box<Mapping>` に置き、`Machine` 本体を大きくしない。
4. 変換後の範囲を確認した値でRAMへアクセスする。unsafeや境界検査の強制省略は使わない。

CPU命令の意味、I/O位置の変更、ROM、未搭載バンク、保護ビット、タスク切り替え、固定上位RAMの意味は維持する。
CPUのフラグ式やword inlineの変更は最終的に戻した。
`Box` 分離の効果は観測したが、ハードウェアのキャッシュミス削減などの機構を測定したわけではない。
型の選択だけで一般に速くなるとは主張しない。

## 最終比較

同じホスト（Ryzen 9 9900X / WSL2 / rustc 1.99.1）で前後を交互に各7回測定。

| 固定小数点マンデルブロー | 中央値 | MHz相当 |
|---|---:|---:|
| 前回採用版 | 0.972388秒 | 504.6 |
| 今回採用版 | 0.877501秒 | 559.2 |

**処理速度1.108倍、時間約9.8%短縮。** これは今回の前後比較であり、第0版からの改善率ではない。

別の6809機械語ループもCPU 0へ固定し、実行順を変えて各5回測定した。
各負荷で最終RAM/CPUチェックサム、仮想サイクル数、ステップ数、送信バイト数が一致した。
シリアル負荷はACIAに送信するが、ホスト端末へ表示する時間は含めない。

| 1億仮想サイクルの負荷 | 前回版 | 今回版 |
|---|---:|---:|
| 通常RAMでindexedアクセス | 0.15335秒 | 0.15500秒 |
| MMU有効でindexedアクセス | 0.21801秒 | 0.19926秒 |
| ACIA出力中心 | 0.14632秒 | 0.14371秒 |

通常RAMは約1%遅く、MMU使用時は約9%短縮、シリアルは約2%短縮。
短い計測の小さな差はノイズもあるため、「全用途で高速化」とは解釈しない。

## 検証

21件のテスト成功、Clippy警告なし、整形確認済み。
MMUの全256エントリ値×8ページ×2タスクについて、読み取り先と保護を確認するテストを追加した。
無視される制御書き込み、MMU無効化、ROM、固定上位RAM、SD、OS・BASIC09・Cコンパイルも検証した。

```sh
python3 scripts/experiment-patterns.py
python3 scripts/benchmark-core-patterns.py
python3 scripts/benchmark-core-patterns.py --interleaved --pin --runs 5
python3 scripts/compare-benchmarks.py --workload fixed \
  --baseline artifacts/optimization/round2/base/rs6809 \
  --output artifacts/benchmark/paired.json
```

試作は `artifacts/optimization/round2/base/source.tar.gz` を元に別ディレクトリへ構築する。
測定結果とソースハッシュは `docs/pattern-validation.json`、生データ・バイナリ・採用ソースのアーカイブは
`artifacts/optimization/round2/` に保存した。
凍結入力がない場合、比較ツールは新しいデモを代用せずエラーにする。

release設定と属性の意味は [Cargoのprofile仕様](https://doc.rust-lang.org/cargo/reference/profiles.html) と
[Rustのinline/cold仕様](https://doc.rust-lang.org/reference/attributes/codegen.html) を参照。
