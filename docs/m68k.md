# 68000 CPUコア

`src/m68k/` は、Motorola 68000の命令単位のインタプリタです。6809のコア（`src/cpu.rs`）とは別に動き、外部crateを使いません。
ICEへの組み込み（CPUの差し替え）は段階2bで行います。

## 使い方

```rust
use rs6809::m68k::{Bus68k, M68k};

struct Ram(Vec<u8>);
impl Bus68k for Ram {
    fn read8(&mut self, a: u32) -> u8 { self.0[a as usize] }
    fn write8(&mut self, a: u32, v: u8) { self.0[a as usize] = v }
}

let mut cpu = M68k::default();
cpu.reset(&mut ram);          // SSPとPCをベクタ0・1から読む
loop { cpu.step(&mut ram); }  // 1命令（または割り込みの受け付け）
```

- **バス**：`Bus68k` は24ビット番地のバイト単位の読み書きで、ワードの読み書きは既定で2回のバイトアクセスになります。
  ワード・ロングの奇数番地へのアクセスはバスに届かず、CPUがアドレスエラーにします。
- **レジスタ**：`d[0..8]`、`a[0..8]`（`a[7]` は実行中のスタックポインタ）、`sr`、`pc`。
  使っていない側のスタックポインタは `usp()`・`ssp()`・`set_usp`・`set_ssp` で読み書きします。
  `set_sr` は、Sビットが変わるとスタックポインタを切り替えます。
- **割り込み**：機械側が `irq`（0〜7）と、必要なら `irq_vector`（ベクタ番号の指定）を設定します。
  `irq_vector` が `None` のときは自動ベクタ（24+レベル）を使います。レベル7はマスクできません。
- **そのほか**：`STOP` 中は `stopped`、二重フォールトで `halted`、`RESET` 命令で `reset_out` が立ちます。`cycles` は累計サイクル数です。

## 実装の範囲

- 68000の全命令（`MOVEP`、BCD演算、`MOVEM`、`CHK`、`TAS` などを含む）、ラインA・ラインF、`ILLEGAL`。
- 例外：アドレスエラー（14バイトのフレーム）、不正命令、特権違反、ゼロ除算、`CHK`、`TRAPV`、トレース、`TRAP`、割り込み。
- サイクル数は命令単位です。MC68000ユーザーズマニュアル8章の表（基本時間＋実効アドレスの計算時間）に、
  除算はJorge Cwik氏によるマイクロコードの解析に従います。
- バスエラー（`BERR`）の入力と、プリフェッチ（命令の先読み）の再現は行いません。PCは次に読む命令語を指します。

## アドレスエラー

68000はアドレスエラーのフレームに、エラーが起きたアクセスの番地・命令レジスタ・SR・状態ワードと、その時点のPCを積みます。
積まれるPCとサイクル数は、命令の処理がどこまで進んだか（拡張ワードの読み込みやプリフェッチ）で決まります。
SingleStepTestsのデータから、次の規則を読み取って実装しました。

| 項目 | 規則 |
|---|---|
| 状態ワード | `(IR & $FFE0) \| R/W<<4 \| I/N<<3 \| FC`。I/Nはプログラム（命令）アクセスで1。FCはエラーが起きたアクセスの機能コード（例外に入る前のモード） |
| 積まれるPC | エラーが起きた時点のPC−2。奇数番地への分岐（`JMP`・`JSR`・`Bcc`・`BSR`・`DBcc`・`RTS`・`RTE`・`RTR`）では分岐先−4 |
| サイクル数 | 50＋エラーまでに使ったサイクル数（拡張ワードの読み込み4、`-(An)` と添字付き番地の内部時間2、読み書き4／ロング8）。分岐ではその命令の通常の時間−8 |
| ロングの番地 | `-(An)` へのロングの書き込みと、`ADDX`/`SUBX -(An)` の読み出しは下位ワードが先なので、番地＋2を報告します |
| 個別の動作 | `JSR` は戻り番地を積む前に分岐先を確かめる（`BSR` は積んだ後）。`MOVE` の書き込み先が `(An)+` なら、失敗したとき `An` は増えない。`-(An)` なら書き込みの前に次の命令を先読みする（PC＋2、サイクル＋4、ロングでは `An` が2だけ減った状態）。`(xxx).L` はメモリからの転送のとき、番地の2語目を読む前に書く。`MOVEM (An)+` は1語分進んだ状態。`ADDX`/`SUBX.l -(An)` は2だけ減った状態 |

## 検証

```sh
python3 scripts/fetch-68000-tests.py                               # 初回のみ（約250MB）
cargo test --release --test m68k_sst -- --ignored --nocapture     # 命令テストと逆アセンブラ
cargo test --release --test m68k_core                              # 割り込み・STOP・トレースなど
```

[SingleStepTests/680x0](https://github.com/SingleStepTests/680x0)（v1、コミット `e0d5ece`）は、125ファイル・約100万件の命令単位のテストです。
ライセンスの表記がないため、リポジトリには含めず、取得スクリプトでダウンロードして2進形式に変換します（`artifacts/sst68000/`）。
各テストで1命令を実行し、レジスタ・SR・PC・RAM・サイクル数を比べます。プリフェッチの状態とバスの読み書きの順序は比べません。

| 区分 | 件数 | 一致 |
|---|---|---|
| アドレスエラー以外 | 821,970 | すべて（下の3件を除く） |
| アドレスエラー | 178,087 | すべて（フレーム全体・レジスタ・サイクル数まで） |

除外した3件：

- `ASL.b Q, D2` の1583番・1761番：データの誤り（取得元のIssue #4）。こちらの結果は、Issueで示された正しい値と一致します。
- `DIVU (d16, A7), D0` の5745番：データ全体で唯一のゼロ除算で、命令の先頭番地を積んでいます。
  マニュアルでは次の命令の番地を積み、`CHK`・`TRAPV` の数千件のテストもそうなっているので、マニュアルどおりにしています。

テストデータにない動作（リセット、割り込みのマスク・自動ベクタ・ベクタ指定・レベル7、`STOP`、トレース、特権違反、
`ILLEGAL`・ラインA/F、`RESET` 命令、`TRAP` と `RTE`）は `tests/m68k_core.rs` で確かめます。

逆アセンブラ（`m68k::disasm`）は、命令テストの全件（1,000,060件）で、命令の種類とサイズがファイル名と一致すること、
分岐しない命令では命令長が実行後のPCの進み幅と一致することを確かめています。

## 機械の構成に向けた調査

- FUZIXのTiny68K版の起動ローダー（`Kernel/platform/platform-tiny68k/loader.S`）は、モニタROMの「CP/M起動ローダー」から呼ばれますが、
  その後はモニタを使わず、68681 DUART（`$FFF000`）とIDEを直接操作します。
  エミュレータがディスクの起動ローダーをメモリに読み込んで開始すれば、モニタROMがなくても起動できる見込みです。
- Tiny68KのモニタROM（`T68kbug_r07.BIN` など）は retrobrewcomputers.org で配布されていますが、
  Cloudflareの確認画面があるため自動では取得できず、配布条件も確認できていません。
